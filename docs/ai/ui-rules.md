# UI Rules

Design for users and for reliable AI verification.

## Verify-by-Design
Prefer UI that can be checked by component tests, headless browser tests, screenshots, accessibility checks, and simple DOM assertions.

## Prefer
Simple pages, cards, lists, tables, drawers, modals, clear buttons, visible status badges, simple tabs, ordinary forms, empty states, confirmation dialogs.

## Avoid Unless Required
Drag-and-drop workflows, hover-only controls, complex canvas UIs, animation-heavy interactions, resizable dashboards, real-time collaborative editing, deeply nested modals, dense chart dashboards, map-heavy UI, highly dynamic layouts.

## Page Structure
Unless project rules say otherwise: title/explanation, primary action, summary cards if useful, one main work area, one helper/secondary panel if useful. Avoid clutter.

## UI Checklist
- [ ] Primary action obvious
- [ ] Hierarchy clear
- [ ] Copy plain
- [ ] Buttons look like buttons
- [ ] Statuses visible
- [ ] Empty state explains next action
- [ ] Errors understandable
- [ ] Layout does not overflow
- [ ] Mobile/narrow layout considered
- [ ] No unnecessary charts/filters/widgets

## Accessibility Basics
Semantic buttons/links, labels for inputs, do not rely only on colour, readable text, focus states, reasonable click targets, understandable errors.
